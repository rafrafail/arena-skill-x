# Trix Arena

Плагин **Trix Arena** для Trix Agent: турнирная арена для промптов. Команда
`/arena` запускает N независимых LLM-участников на одну и ту же задачу — каждый
со своей **strategy card** — и проводит одиночную сетку на вылет
(spawn → attack → defend → judge, раунд за раундом), пока не останется одно
выжившее решение. Движок детерминирован: одинаковый `--seed` даёт одинаковую
раздачу карт и одинаковую сетку.

Технический id: `trix-arena`. Версия: 0.1.0.

---

## Что делает плагин

- Каждый участник получает **одну и ту же задачу** и **уникальную тройку
  стратегий** (карту подхода, карты стиля и т.д. — раздаются детерминированно
  из сида).
- Участники встречаются в **одиночной сетке на вылет**. Каждый матч — это
  фазы: `attack` (2 вызова: каждая сторона атакует решение соперника),
  `defend` (2 вызова: каждая сторона защищается), `judge` (1 вызов: вердикт).
  Итого **5 LLM-вызовов на матч** (`CALLS_PER_MATCH = 5`).
- Нечётное число живых участников: ровно один получает **бай** (проходит раунд
  без матча). В раунде играет `floor(alive/2)` матчей, поле сокращается до
  `ceil(alive/2)`; бай на раунд — не более одного.
- Финал: последний живой объявляется чемпионом. Дополнительная фаза `final`
  (матч чемпиона против baseline-решения) существует в движке, но в план
  стоимости не входит и tool-API не включается (см. «Честные ограничения»).

## Установка

Плагин живёт в репозитории в `plugins/trix-arena/`:

```
plugins/trix-arena/
├── plugin.yaml          # манифест: id, версия, команда /arena, 6 инструментов
├── __init__.py          # register(context): /arena + arena_* tools
├── schemas.py           # строгие входные схемы инструментов
├── commands.py          # парсер /arena (6 подкоманд)
├── tools.py             # тонкая обёртка над движком
├── arena/               # ядро: core.py (движок) + orchestrator.py + __init__.py
├── skills/trix-arena/SKILL.md   # UX-документация /arena для агента
├── tests/               # pytest-набор (python3 -m pytest plugins/trix-arena/tests/)
└── data/                # стратегии карт
```

Подключение: плагин регистрируется функцией `register(context)` из
`plugins/trix-arena/__init__.py` — она добавляет команду `arena` и шесть
инструментов `arena_ping`, `arena_plan`, `arena_start`, `arena_status`,
`arena_cancel`, `arena_result`. Внутри репозитория пакет импортируется как
`trix_arena` (см. `tests/conftest.py`).

## Команда /arena

Шесть подкоманд; парсер строгий (флаги только в форме `--name value`,
`true|false` для булевых; неизвестная опция, одиночный дефис, пропущенное
значение или неверный тип — однострочная ошибка, ничего не угадывается):

| Подкоманда | Назначение |
|---|---|
| `/arena ping` | проверка живости; отвечает ровно `pong` |
| `/arena plan [--agents N] [--wave N]` | предпросмотр стоимости (раунды/вызовы/волны), без состояния |
| `/arena start <task> [--agents N] [--seed S] [--wave N] [--dir PATH]` | создать ран: раздать карты, открыть раунд 1; ран становится LATEST |
| `/arena status [--run ID] [--dir PATH]` | осмотреть ран: живые, текущий раунд, незаписанные матчи, недостающие задачи по фазам (read-only) |
| `/arena result [--run ID] [--dir PATH]` | собрать вердикты судей с диска, report чемпиона, финала и исходов матчей |
| `/arena cancel [--run ID] [--dir PATH] [--purge true\|false]` | отменить ран; `purge=true` — удалить его директорию; снимает указатель LATEST, если он ссылался на ран |

Примеры:

```
/arena ping
/arena plan --agents 100
/arena start "спроектируй кэш LRU с O(1) get/put" --agents 16 --seed lru --dir .arena
/arena status
/arena result
/arena cancel --purge true
```

Те же операции доступны как инструменты `arena_*` (см. `plugin.yaml`). Контракт
инструментов: каждый возвращает dict с ключом `ok` — `{"ok": True, ...}` или
`{"ok": False, "error": "..."}`; инструменты **никогда не бросают исключения**
наверх (единственное исключение — `KeyError` для неизвестного имени инструмента
в реестре схем, это ошибка конфигурации хоста, а не пользовательский ввод).

## Режимы и стоимость в вызовах

Размер поля задаётся `--agents N` (от 1 до количества комбинаций карт;
ориентир — до 2160). Предустановки: **quick** = 16 (`QUICK_AGENTS`),
**full** = 100 (`DEFAULT_AGENTS`), **custom** = любое N в пределах лимита.

Формула плана: **вызовы = N (spawn) + 5 × (N − 1) матчей**; матчей в сумме
ровно N − 1; волны — это батчи задач по `--wave` (по умолчанию 10);
`--wave` меняет только разбиение на батчи, но не число вызовов.
`/arena plan` показывает по-раундовую разбивку.

| agents | раундов | LLM-вызовов | волн (wave=10) |
|---:|---:|---:|---:|
| 1 | 0 (+1 spawn) | 1 | 1 |
| 4 | 2 | 16 + 5×3 = 31 | — см. `/arena plan` |
| 16 (quick) | 4 | 91 | 16 |
| 100 (full) | 7 | 595 | 70 |

Для 100 участников сетка: 100 → 50 → 25 → 13 → 7 → 4 → 2 → 1
(50+25+12+6+3+2+1 = 99 матчей ⇒ 100 + 495 = 595 вызовов). Для 16:
16 → 8 → 4 → 2 → 1 (15 матчей ⇒ 16 + 75 = 91). Нечётные раунды (25 → 13 и т.п.)
содержат один бай.

## Формат финального ответа

- `/arena result` сообщает: чемпиона, `finished` (чемпион есть и финал
  отсужён), счёт финала — `final: <better> is better (champion <total> vs
  baseline <total>) <reason>` — и список собранных вердиктов по матчам
  (id матча, статус, примечание; нечитаемые вердикты помечаются и уходят в
  карантин `.unreadable`).
- Чемпион — единственный живой участник последнего раунда; проигравший в
  каждом матче фиксируется в состоянии (`eliminated_in`, `eliminated_by`) и
  больше не играет.
- Оценка вердикта — взвешенная сумма по осям correctness/robustness/
  efficiency/clarity/style с весами **30/25/15/20/10** (`WEIGHTS`); решения
  хранятся на диске дословно (verbatim).

## Детерминизм и гарантии

Проверено тестами (`plugins/trix-arena/tests/`):

- одинаковый `--seed` → одинаковая раздача карт и сетка: идентичный чемпион,
  идентичные победители матчей и число вызовов в разных директориях ранов;
- исключённый участник больше никогда не играет; чемпион ровно один;
  дублирующихся карточных троек нет; всего матчей ровно N − 1; бай — не более
  одного на раунд; последний раунд — один матч, его победитель — чемпион;
- E2E-прогон при любом размере совпадает с планом `plan_totals` по вызовам,
  задачам и волнам;
- состояние — версионированный JSON (`state_schema_version`), при чтении
  старые схемы мигрируют на месте.

## Оркестрация (как гонять турнир)

В плагине **нет встроенного LLM-раннера**: движок выдаёт задачи, а вызывающий
передаёт `backend` — callable, который исполняет одну задачу. Контракт —
`arena.orchestrator`: `execute_job(state, job, backend)` по одной задаче или
пакетный прогон по волнам (`wave_batches`); каждая задача имеет
**идемпотентный ключ** (32 hex-символа, зависит от имён выходов — детерминирован
при сохранении/перезагрузке состояния), что позволяет безопасно повторять и
возобновлять прогон. Политика повторов — до `MAX_RETRIES + 1` попыток;
`pause/cancel/resume` — по флагам состояния; после карантина нечитаемого
вывода (`.unreadable`) оркестратор переходит в контролируемую паузу.

## Безопасность

- Участники не получают shell, доступ к файловой системе или сеть — только
  текст задачи, карты и решений; вывод хранится дословно.
- id рана проверяется на path traversal: путь, выходящий за базовую директорию
  арены, отклоняется (`ArenaError`).
- Плагин пишет только внутрь директории рана и файла `<base>/LATEST`;
  относительные пути остаются относительными (абсолютные пути в состоянии не
  хранятся); `purge` удаляет ровно директорию рана.

## Честные ограничения

- **Нет встроенного LLM-раннера** — бэкенд-колбэк предоставляет вызывающий;
  плагин не ходит в сеть и не хранит ключей.
- **Судья эвристичен**: вердикт — это JSON, оцениваемый взвешенной суммой;
  судья-LLM может ошибаться или вернуть нечитаемый вывод (тогда — карантин
  `.unreadable` и контролируемая пауза).
- **`cancel` терминален**: отменённый ран не возобновляется; `purge` — без undo.
- **Фаза `final` (матч против baseline) в tool-API не подключена** и в план
  стоимости не входит: план покрывает ровно spawn + сетку; базовый матч
  добавляется только через `new_state(has_baseline=True)` в движке (+1 вызов).
- Верхняя граница участников — число комбинаций карт (`combo_count`), а не
  произвольное число.
